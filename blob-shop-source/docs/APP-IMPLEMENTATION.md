# Blob Shop — приложение

19 октября 2026. Локальная реализация на Three.js / Vite / ванильном JavaScript. Отдельные GLB загружаются из собственного набора проекта. Остановленная Blender-сцена не импортируется.

## Файлы

- `src/main.js`: сборка сцены, свет, обычный Pointer Events ввод, текущие экземпляры предметов, управляемое поглощение, постоянные крепления/лицо, выдача, адаптивная камера и диагностический снимок.
- `src/orders.js`: чистая модель точного состава, резервы трёх игрушек, выборочное извлечение, последовательность капсул, атомарный колокольчик и три заказа.
- `src/assets.js`: GLBLoader, единый масштаб 2.10, общие геометрии/материалы экземпляров, изображения рецептов из тех же GLB.
- `src/customer.js`: измеренные sourceRect RGBA-атласа, нормирование по одинаковой высоте и нижнему центру, моргание, взгляд во время работы, переходы поз ошибки/получения/благодарности.
- `src/audio.js`: тихие WebAudio отклики, доступное выключение.
- `src/style.css`, `index.html`: русская оболочка одного экрана, желание, подсказки и завершение трёх заказов.
- `tests/order.test.mjs`: проверки чистой модели, без WebGL/DOM.

Физический адаптер и его vendor находятся в зоне другого исполнителя; это приложение импортирует `ShopPhysics` по `ENGINE-CONTRACT.md`.

## Масштаб и композитинг

Радиус физики остаётся 1.05. Все GLB получают одинаковый множитель 2.10. Столешница counter ставится в Y=0 по метаданным рабочей поверхности: root Y=−1.185×2.10. Мат лежит поверх неё, физический пол Y=.06 близок к рабочей поверхности mat .025×2.10=.0525. Корзина использует внутренний проём 2.5305×2.6145, floorY=.1995, rimY=.735. Мебель и предметы собраны в Three.js.

Камера перспективная, направление `(0,.9,1)`, наклон около 42°. Центральная игровая область ограничена 590 CSS px; фон/клиентка находятся за прозрачной 3D-канвой. У клиентки нет слоя поверх корзины: целая фигура остаётся за настоящей рабочей зоной. Нормальные тени и свет относятся к 3D; фон содержит нарисованное освещение. Лицо и внешние детали используют постоянные barycentric anchors физической оболочки, без подмены camera-facing ориентацией.

После геометрической приёмки центр корзины Z=−1.05, центр коврика Z=−.93; лотки Z=1.50, ряды добавок Z=.83 / 2.20, колокольчик X=3.20 / Z=.84. Единый масштаб GLB сохранён. Между передним краем коврика и задним краем лотков остаётся зазор .015. Расчётная минимальная дистанция между центрами выбора добавок при 360×740 — около 46.3 CSS px; это геометрический расчёт, не браузерный или телефонный тест. Выбор добавки выполняется одним `raycaster.intersectObjects`, берётся ближайшее пересечение по расстоянию луча; при отсутствии пересечения действует ближайшая отдельная экранная зона.

## Состояния и ввод

Материал начинает как невыбранный в данных, хотя чистый блоб показан аква-оболочкой. Капсула применяется только после явного перемещения и отпускания на теле. Последовательность `materialSequence` не допускает отката от позднего callback предыдущей капсулы. Новый профиль полностью заменяет материал и физику существующего тела; состав сохраняется.

Игрушка получает резерв при начале поглощения. Три места включают pending/inside/extracting. Капсула места не занимает. Одна фиксация по id после автоматического перехода; повторные callbacks игнорируются. Поглощение — управляемая траектория с локальным нажимом, не жидкость. Игрушки остаются жёсткими и сохраняют исходный размер. Их центр следует COM/физическому ориентиру, при сжатии проверяется `containsSphere`.

Pointerdown выбирает видимый отдельный предмет, внутренние игрушки доступны через прозрачную оболочку. Выбранный предмет выделяется светлым кольцом. При извлечении резерв сохраняется до отпускания: требуется движение более .55 единицы от исходной позиции и полное расхождение world-space AABB всего предмета и оболочки. Перемещение внутри тела или частичный выход не удаляют предмет из состава: восстанавливается его исходное состояние и показывается «Вытяните предмет за край блоба». Отмена возвращает только выбранный экземпляр. Успешно извлечённый предмет остаётся на столе. В текущем жесте он не запускает магнит, повторное применение требует нового захвата и броска.

Раннее движение по телу тянет локальный участок. Быстрый выход за исходный силуэт переводит в перенос целиком с подсветкой и подъёмом над бортом. Неподвижное удержание .45s включает физический whole grab; движение одного пальца задаёт относительный виртуальный trackball-поворот частиц. Отпускание снимает хват и сохраняет достигнутую ориентацию. Это разные способы одного жеста, без экранных кнопок поворота.

`pointercancel`, lost capture, blur, visibility change, resize и второй палец снимают активный жест. Отмена до броска не применяется. Начавшееся после release автоматическое поглощение живёт независимо от указателя и безопасно приостанавливается в скрытой вкладке.

Колокольчик проверяет полный `fitsBasket`, отсутствие хвата, короткую стабильность .35s, завершённость переходов и точный состав. Ошибка оставляет того же клиента и сборку, называет материал/недостающее/лишнее. Принятие одного заказа атомарно. После трёх есть повтор; текущий заказ можно начать заново через «Как играть». Reload начинает с первого заказа, постоянного сохранения нет.

## Диагностика и проверка

`?qa` показывает метрики и предоставляет read-only `window.__blobShopQA`: состав, состояния предметов, экранные координаты, finite/volume/heldMode, render counts. Методов подстановки/автозачёта/перезапуска нет. Обычный игровой экран технических терминов не показывает.

В ходе реализации выполнены `node tests/order.test.mjs`: 11 проверок пройдены. `npm run build` прошёл. Реальные проверки ввода и снимки сцены записываются после готовности локального сервера в `qa/app/`. Эмуляция viewport сама по себе не доказывает ощущения и производительность на Galaxy S21 Ultra. Субъективное качество и живой телефон требуют проверки пользователя.
